### 本轮发现的 P0 发布问题

- 现象：从 Git 导出的干净副本无法启动，`app.json` 报底部栏 8 个 PNG 图标未找到。
- 原因：图标只在原电脑上存在，整个 `miniprogram/images/` 目录被 Git 忽略；旧引用校验只检查本机文件是否存在，未发现发布遗漏。
- 修复：只将底部栏实际引用的 8 个图标纳入版本管理，其他旧模板图片继续忽略。引用校验现在同时检查文件存在和是否会被 Git 忽略，覆盖页面、图标、本地图片和 JS 相对导入。
- 回归证据：增强后的校验在修复前确实拦截 `goods.png`；补齐资源后通过，游客副本首页实际启动。本轮还使用干净的暂存树导出验证全部引用及 25 项自动回归，防止依赖原电脑的隐藏文件。

## 二手商品

- 浏览商品：进入“二手”tab，默认只看到“在售”商品，两列瀑布流上下错落。
- 瀑布流顺序：最新两件商品分别在左右两列顶部；横图、竖图保留原比例，标题最多两行，不出现等高卡片或单列回退。
- 图片加载：浏览中图片加载完成不应让卡片突然换列；图片失败显示“暂无图片”，下拉刷新可以重试。
- 状态筛选：切换“全部 / 在售 / 已售 / 已下架”，确认列表状态符合筛选。
- 搜索商品：搜索标题、描述、分类，例如 `显示器`、`教材`、`厨房用品`。
- 搜索空结果：输入不存在的关键词，确认出现空状态提示。
- 清空搜索：点搜索框右侧清空按钮，确认恢复默认在售列表。
- 手动清空搜索：在其他状态筛选下搜索，再删除全部关键词，确认同样恢复在售列表。
- 无图片商品：查看无图片商品卡片和详情页，确认占位图正常。
- 超长标题：查看超长标题商品，确认首页最多两行，详情页可完整查看。

## 发布与编辑

- 发布商品：从“我的”页点击“发布商品”，未登录也能进入；填写标题、价格、分类、成色、地点、描述后提交。
- 价格为空：价格留空提交，确认提示“请填写价格”。
- 价格非数字：输入非法价格，确认提示“价格只能填写数字，最多两位小数”。
- 必填定位：标题、价格、地点全部留空后发布，三个输入框分别出现错误提示，焦点定位到标题；修改其中一项只清除该项提示。
- 图片上传：上传 1-9 张图片，确认不会超过 9 张。
- 图片重选：删除选错的图片后重新选择，点击缩略图可预览；编辑时删除最后一张图，确认商品变为无图占位。
- 图片持久保存：带图发布后关闭小程序，再重新进入，确认首页和详情图片仍正常。
- 取消选图：打开相册后取消，确认仍可再次选图、提交。
- 重复提交：连续点击提交，确认只新增一件商品。
- 保存失败：模拟本地存储不足或失效图片路径，确认保留输入、结束 loading，修正后可以重试。
- 编辑商品：登录后进入自己发布的商品详情，点“编辑商品”，修改后保存。
- 非本人商品不能编辑：登录后打开非 `CUHK Student` 发布的商品，确认不显示管理按钮；手动进入编辑页也会被拦截。
- 权限变化：打开编辑页后清除登录状态，再提交，确认原商品不被修改，也不会误创建新商品。

## 详情图片

- 多图浏览：发布三张横竖比例不同的图片，详情可左右滑动，完整显示图片，并更新右下角张数。
- 当前图预览：滑动到第二或第三张再点击，预览从当前图片开始；返回详情后仍停在原来的位置。
- 坏图隔离：其中一张加载失败时显示占位，其余图片仍可浏览和预览；点击坏图提示暂时无法预览。
- 图片变更：编辑商品删除或替换图片后返回详情，图片列表和当前页正确更新。
- 缺少商品 ID：直接打开不带参数的详情页，显示“商品已删除或不存在”，不出现 JS 错误。

## 商品状态

- 下架商品：登录后打开自己的商品，点“修改状态 → 下架商品”，二次确认后状态变为“已下架”。
- 标记已售：登录后打开自己的商品，点“修改状态 → 标记已售出”，确认状态变为“已售出”。
- 预订与取消：选择“标记已预订”后显示预订标签，再选“恢复在售”，确认默认商品流恢复展示。
- 重新上架：在“我的发布”打开已下架或已售商品，选择“修改状态 → 恢复在售”，确认首页、详情和我的发布同步。
- 删除商品：登录后打开自己的商品，点“删除”，确认出现二次确认，确认后首页不再显示该商品。
- 删除后的详情：从旧路径打开已删除商品，确认出现“商品已删除或不存在”，没有管理和联系按钮，可返回首页。
- 删除异常：自动回归注入商品写入失败时，应保留商品和收藏；仅收藏清理失败时，已删除商品仍正确消失，不误报删除失败。
- 已售商品：切换首页“已售”，确认能看到已售商品。
- 已下架商品：切换首页“已下架”，确认能看到已下架商品。

## 联系与举报

- 查看联系方式：未登录时详情页显示“登录后查看联系方式”。
- 模拟登录：点详情页登录按钮，登录后返回详情页，确认显示微信号。
- 单独进入登录页：模拟登录后回到“我的”页，确认不会停在登录页。
- 复制微信号：点“复制微信号”，确认 toast 提示复制成功。
- 我联系过的商品：复制微信号后进入“我的”，确认商品出现在“我联系过的商品”。
- 举报：点“举报”，选择原因，确认出现“举报已提交”提示。
- 分享文案：复制成功时显示成功提示；剪贴板操作失败时提示重试，不显示复制成功。

## 收藏与我的

- 收藏商品：详情页点“收藏”，确认按钮变为“已收藏”。
- 取消收藏：再次点击，确认取消收藏。
- 我的收藏：进入“我的”，确认收藏商品出现在“我的收藏”。
- 收藏异常：自动回归注入收藏写入失败时，按钮和收藏列表保持原状态；恢复写入后可正常重试。
- 我的发布：登录后进入“我的”，确认自己发布的商品全部展示，包括已售、已下架。
- 退出登录：点“退出登录”，确认用户信息、我的发布和联系记录按未登录状态展示。
- 退出后的旧详情：回到商品详情，确认微信号已隐藏；即使旧页面仍有缓存，复制操作也不会泄露联系方式。

## 通过标准

- 页面跳转不卡死。
- 商品列表、详情、发布、编辑、状态变更、收藏、联系记录都使用本地 mock 数据正常闭环。
- 非 owner 看不到管理按钮，也无法直接编辑非本人商品。
- 清理缓存后重新进入，小程序仍能加载默认 mock 商品。

## 第二阶段：两台手机交易验收

第一阶段通过后，再接入最小云端服务。范围只包括共享商品、云端图片、基础用户身份和服务端商品操作权限；保留本地 mock 版作为可回退的演示与测试数据源。暂不扩展拼团、求购、地图、管理后台或网页端。

使用两台手机、两个不同用户身份，按以下顺序验收：

1. 甲发布带图片的商品，记录商品 ID、标题、价格和交收地点。
2. 乙在自己的手机上刷新或搜索，看到同一商品和图片，字段与甲一致。
3. 乙登录后查看并复制甲的联系方式；未登录时不能获取联系方式。
4. 乙不能编辑、改状态或删除甲的商品，服务端也必须拒绝越权请求。
5. 甲将商品标记为已预订，乙刷新后看到对应状态。
6. 甲将商品标记为已售出，乙刷新后看到已售状态，默认在售流不再展示该商品。
7. 两台手机分别关闭并重新进入，确认商品状态、图片和发布者身份仍正确。

先完成上述跨设备闭环，再邀请 3-5 位 CUHK 同学进行真实交易试用。仅向不同手机分发独立 mock 版本，可以验证单机交互，但不能计作跨用户交易验收通过。当前第二阶段尚未开始。
